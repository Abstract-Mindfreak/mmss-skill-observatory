# MMSS Skill Observatory

**Instruction Atlas · Behavior Lab · Evolution Studio** — исследовательская среда для чтения,
анализа, испытания и развития инструкций AI-агентов.

Первый исследуемый документ — SKILL.md скилла [`mmss-principle-synthesis` v0.1.4](https://github.com/Abstract-Mindfreak/mmss-principle-synthesis)
(файл-вложение идентичен репозиторию, sha256 `ddd187d4…`, сверка доступна в разделе «Обзор»).
При первом открытии приложение автоматически создаёт исследовательский проект с этим документом,
его структурным разбором и стартовым деревом сценариев — панель не пустая.

Встроенная копия скилла принадлежит Andrey Mundrievskiy (Abstract-Mindfreak) и взята из [исходного репозитория](https://github.com/Abstract-Mindfreak/mmss-principle-synthesis): `src/seed/mmss-principle-synthesis.SKILL.md`. Её MIT License находится рядом: `src/seed/mmss-principle-synthesis.LICENSE`. Эта лицензия относится только к копии скилла; лицензия приложения S2 отдельно не выбрана.

## Возможности (кратко)

- **Instruction Atlas** — полный текст с масштабированием документ → раздел → абзац → предложение → слово,
  15 переключаемых визуальных слоёв (обязательства, запреты, разрешения, условия, исключения,
  определения, требования к доказательности, неизвестности, неоднозначность, повторы, конфликты,
  покрытие сценариями…), карточка фрагмента с основаниями каждой классификации, модельные
  интерпретации, заметки, поиск.
- **Карта правил** — интерактивный граф (~570 узлов / ~950 связей для базового документа):
  типизированные связи с основаниями, фильтры по типам/разделам/тексту, статистика
  (центральные узлы, мосты, изоляты, дубликаты, цепочки, непокрытые разделы).
- **Failure Roads** — дорога решения задачи (7 стадий по разделам скилла) с развилками и каталогом
  «ям» потенциальных отказов; каждое «яма» привязана к конкретному фрагменту документа.
- **Scenario Tree** — многомасштабное дерево ситуаций со статусами
  (неисследованная / исследованная / синтетическая / проверена запуском / оспорена / остановлена),
  рост через Explorer-роль, бюджет запусков, экспорт ветвей.
- **Behavior Lab** — роли Executor / Explorer / Evaluator / Challenger / Editor, реальные запуски
  моделей, локальные программные проверки (валидность JSON, NaN/Infinity, дубликаты ключей),
  вердикты с разделением «вердикт модели» и «вердикт пользователя», серии запусков, отмена,
  повтор, отображение разногласий оценщиков.
- **Evolution Studio** — версии и экспериментальные ветки, diff (строки + слова), анализ последствий
  правки **до** сохранения (изменившиеся обязательства, сценарии к повтору, устаревающие результаты,
  стоимость A/B/C/D), восстановление версий, импорт документа, сверка с GitHub-репозиторием.
- **Метрики** — 10 показателей с паспортом каждого (определение, метод, ограничения, выборка):
  слои по разделам, покрытие сценариями, плотность определений, неоднозначность, распределение
  находок, запуски по статусам и вердиктам, расхождения оценщиков, время выполнения, сравнение версий.
- **Подключения** — кабинет Ollama: адрес, проверка соединения, список моделей с определением
  возможностей, пробные генеративные и embedding-запросы, назначения моделей на роли;
  статус облачного бэкенда сессии разработки.
- **Экспорт и передача** — копирование фрагментов/карточек/разделов/отчётов, скачивание
  Markdown / JSON-архива / CSV, **Research Handoff Report** (цель, документ, изменения, анализы,
  запуски, находки, основания, спорные выводы, гипотезы, ошибки, ограничения, заглушки, следующие
  шаги), импорт архива с проверкой формата.
- **Реестр статусов** — честные статусы всех функций (LIVE / LOCAL / DEMO / PLACEHOLDER / STALE / ERROR),
  загрузка/очистка демо-данных, список заглушек с обходными путями.
- **Помощник** — чат с контекстом выбранного фрагмента (один из инструментов, не основа интерфейса).

## Запуск локально

Требования: Node.js 20+ или Bun 1.1+.

```bash
# 1. Установить зависимости
bun install        # или npm install

# 2. База данных (SQLite) — применить схему
bun run db:push    # или npx prisma db push

# 3. Запуск в режиме разработки
bun run dev        # или npm run dev
```

Откройте <http://localhost:3000>. При первом открытии создастся сид-проект с прикреплённым
SKILL.md (файл лежит в `src/seed/mmss-principle-synthesis.SKILL.md`).

> Продакшен-сборка: `bun run build && bun run start` (скрипты уже настроены).

## Подключение Ollama (локальные модели)

Приложение работает с вашей локальной Ollama — облачные сервисы для этого не нужны.

1. Установите [Ollama](https://ollama.com) и скачайте модели, например:
   ```bash
   ollama pull llama3.1          # генеративная модель
   ollama pull nomic-embed-text  # embedding-модель (для проб)
   ```
2. Проверьте, что Ollama отвечает: `curl http://localhost:11434/api/tags`
   (браузер и приложение запущены на одной машине — этого достаточно).
3. В приложении откройте **«Подключения»** → «Добавить подключение»:
   имя — произвольное, адрес — `http://localhost:11434`.
4. «Проверить соединение» → «Обновить модели» → выполните пробный запрос и пробный embedding.
5. Назначьте модели ролям (Executor / Evaluator / …) — или выбирайте модель при каждом запуске.

**Безопасность:** не открывайте Ollama в интернет (например, через `OLLAMA_HOST=0.0.0.0` без
авторизации) ради этого приложения. Если браузер на другой машине — используйте ssh-туннель:
`ssh -L 11434:localhost:11434 <server>` и адрес `http://localhost:11434`. Приложение обращается
к Ollama со своего сервера; секреты не хранятся и не встраиваются в клиент и экспорты.

**Проверка реальности запросов:** в разделе «Подключения» у каждого подключения виден статус
«проверено реальным ответом» — он выставляется только после успешного ответа Ollama. Запуски в
Behavior Lab показывают бэкенд и модель каждого запроса; ошибки выводятся как есть и никогда
не подменяются синтетикой.

### Что такое «облачный бэкенд сессии»

В среде разработки, где проект был создан, доступен временный облачный LLM-бэкенд (z-ai-sdk).
Он помечен как существующий **только внутри сессии разработки** и исчезает вместе с ней.
Для локальной работы используйте Ollama. Без подключений приложение остаётся полноценно
полезным: чтение, слои, граф, дороги, заметки, версионирование, локальный анализ, экспорт.

## Где хранятся исследования

- **База данных:** `db/custom.db` (SQLite). Всё — проекты, версии документов, фрагменты, анализы,
  сценарии, запуски, находки, заметки, подключения, чат — в одном файле.
- **Резервная копия:** скопируйте `db/custom.db` (при остановленном `bun run dev`).
- **Перенос:** «Экспорт и передача» → «Архив проекта (JSON)» — полный архив с содержимым версий;
  импорт на другой машине: «Импорт» в том же разделе (проверка формата, понятные ошибки).
  Подключения Ollama в архив не входят — их нужно указать заново (намеренно, без адресов и секретов).

## Спецификация и история разработки

- Текущая согласованная спецификация интерфейса автоматизированного исследования: `docs/S2-UI-REMODIFICATION-MMSS.json`.
- История разработки, обзоры, диагностика, приёмка и очищенные отчёты кампаний: `worklog.md` и каталог `docs/`.
- Исторические документы отражают состояние проекта на дату их создания; их выводы не обязательно описывают текущую реализацию.
- Рабочая SQLite и локальные настройки (`.env`, подключения и локальные пути) в репозиторий не входят.

## Честность статусов

Каждый результат в интерфейсе помечен: **LIVE** (реальное выполнение через сервис), **LOCAL**
(реальное локальное вычисление), **DEMO** (синтетика, не входит в метрики), **PLACEHOLDER**
(не реализовано), **STALE** (относится к старой версии данных), **ERROR**. Статус выполнения
(planned/queued/running/completed/cancelled/failed) всегда отделён от вердикта проверки
(pass/fail/inconclusive). Список заглушек — в разделе «Реестр статусов» и в handoff-отчёте.

## Зависимость от облачной среды

- Исходный код, база, анализ, экспорт — полностью локальные.
- Временный облачный бэкенд (`src/lib/session-cloud.ts`, z-ai-sdk) — опционален и доступен только
  в сессии разработки, где проект собран; локально просто не используйте его.
- Сверка с GitHub (`check-remote`) требует доступа в интернет; без него показывает честную ошибку
  и не меняет базовую версию.
