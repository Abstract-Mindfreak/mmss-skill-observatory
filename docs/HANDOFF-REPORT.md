# Research Handoff Report — MMSS Skill Observatory

Документ передачи следующему разработчику/агенту. Дата: 2026-10-19.
Этот отчёт — о состоянии реализации, а **не** доказательство работоспособности интеграций:
все пункты «проверено» ниже перечисляют конкретные средства проверки.

## 1. Цель исследования (проекта)

Исследовательская среда для чтения, анализа, испытания и развития инструкций AI-агентов.
Базовый документ — SKILL.md скилла `mmss-principle-synthesis` v0.1.4 (вложение TASK-задания,
байт-в-байт идентично `skills/mmss-principle-synthesis/SKILL.md` из
github.com/Abstract-Mindfreak/mmss-principle-synthesis, sha256 `ddd187d4cffe8863a07ce812d33de3cb5bd7f557af84b97e6486f79ac9094776`).

## 3. Основной сценарий (как пройти)

1. **Открыть приложение** — сид-проект создаётся автоматически (документ v0.1.4, 1555 фрагментов,
   локальный анализ ~290 мс, 12 стартовых сценариев).
2. **Обзор** — убедиться в подлинности: «Проверить репозиторий» → «Вложение и репозиторий идентичны».
3. **Instruction Atlas** — раскрыть раздел 6.2, кликнуть предложение
   «Do not reconstruct missing content from a title…» → карточка: слой «Запреты» с маркерами,
   связанные сценарии, связи графа.
4. В карточке — **«Интерпретировать фрагмент»** → облачный бэкенд сессии (в среде разработки) или
   Ollama (локально) → интерпретация, альтернативы, область действия, ограничения.
5. Добавить **заметку** к фрагменту (сохраняется в БД).
6. **Behavior Lab** — выбрать сценарий «Обязательный источник недоступен — что вернёт скилл»,
   Executor → «Запустить» → реальный ответ модели + 3 локальные проверки JSON →
   «Оценить результат (Evaluator)» → вердикт (может быть fail — это нормально) → при несогласии
   «Мой вердикт».
7. **Evolution Studio** — «Создать экспериментальную ветку», править фразу →
   «Анализ последствий (без сохранения)» → изменившиеся обязательства, сценарии к повтору,
   STALE-результаты, стоимость A–D → «Сохранить ветку» → diff с origin (пословно).
8. **Экспорт и передача** — Research Handoff Report (все части) → скачать/скопировать;
   «Архив проекта (JSON)» → проверить импорт.

## 4. Реальные и демонстрационные данные

- **Реальные (origin=real):** сид-документ и его версии; локальный анализ; стартовые сценарии
  (origin=seed); заметки; запуски и вердикты, выполненные через интерфейс; интерпретации модели;
  чат; метрики, вычисленные по этим данным.
- **Демонстрационные (origin=demo):** только то, что загружается кнопкой «Загрузить демо-данные»
  в «Реестре статусов» (сценарий «[DEMO]…», 3 запуска, 2 находки). Помечены бейджами DEMO,
  исключены из метрик, удаляются кнопкой «Удалить все DEMO-данные». Не выдаются за исследование
  вложения.
- В момент передачи в сид-проекте: 1 заметка (реальная), 2 реальных запуска (Executor + Evaluator
  через облачный бэкенд сессии), 1 модельная интерпретация, 4 сообщения чата — всё создано при
  проверке интерфейса и является настоящими данными.

## 6. Что НЕ проверено

- **Реальная Ollama:** в среде разработки Ollama недоступна (localhost:11434 не отвечает — среда
  изолирована). Реализован настоящий путь (REST /api/tags, /api/show, /api/chat, /api/embed с
  fallback на /api/embeddings), ошибки протестированы на недоступном адресе, но **успешный вызов
  живой Ollama не выполнялся** — проверьте локально по шагам из README («Подключение Ollama»).
- **Embedding-модели:** проба реализована (размерность + превью вектора), успешный живой ответ
  не проверялся по той же причине. Векторный индекс по документу — PLACEHOLDER (см. §7).
- **Продакшен-сборка** (`bun run build`): среда разработки работает только в dev-режиме; сборка
  не выполнялась. Скрипты стандартные, но проверьте локально.
- **Импорт вручную изменённых архивов** (тамперинг) — проверен только мусорный ввод и валидные архивы.
- **Поведение при concurrency** (два браузера одновременно меняют один сценарий) — не проверялось.

## 8. Ограничения методов (важно для интерпретации результатов)

- Локальный структурный анализ — регресс-эвристики: маркеры модальности, лексическое сходство
  (Жаккард), эвристики конфликтов «противоположная модальность + общий термин». Классификация
  объяснима (каждый слой — с matched/reason/limitations), но не является семантическим пониманием.
- Повторы/сходство — в конкретном лексическом представлении, не доказательство эквивалентности.
- Кандидаты конфликтов — гипотезы с условиями столкновения и условиями оправдания, требуют
  сценарной проверки.
- Графовые связи по терминам/ссылкам — не логические зависимости.
- Failure Roads — редакционная реконструкцией по разделам скилла (не наблюдение внутренних
  рассуждений моделей); наложения из запусков привязаны к разделам сценариев.
- Модельные интерпретации/вердикты — модельная оценка (ProvenanceTag «Оценено моделью»), не факт.
- Метрики вычислены по текущим данным проекта; при 0 данных показывается «Данных нет».
